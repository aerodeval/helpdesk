== account | ostara-learning/ravi | High | Done
# Set up Okta SSO
C: Hi,

We'd like to set up SAML SSO with Okta for all staff. Is there a guide, and can we enforce SSO so nobody can log in with a password?

Ravi Menon
A sofia: Hi Ravi,

Yes to both. The steps are:
1. In Okta, add Fernbill from the app catalog (search "Fernbill"). It fills in the SAML settings for you.
2. In Fernbill, go to Settings > Security > Single sign-on, choose Okta, and paste the metadata URL from Okta.
3. Test with your own account using Test sign-in.
4. Once it works, turn on Require SSO. Password login is then disabled for everyone except the account owner, who keeps a password as a fallback.

If you also want users created and removed automatically, Okta can provision through SCIM. The token is on the same page.

Sofia
C: All set up and enforced. SCIM is working too. Very smooth, thank you.

== account | brightwater-dental-group/marcus | High | Replied | to=sofia
# SSO users getting "Account not found"
C: Hi,

Some staff at our two newest locations get "Account not found" when they sign in with SSO. They're assigned to the Fernbill app in Azure AD and other staff sign in fine.

Marcus Bell
A sofia +1h: Hi Marcus,

Thanks for the details. I've checked a few of the failed sign-ins, and the email Azure sends for these users is their alias, for example dr.lee@brightwater-dental-group.example, while their Fernbill user has their primary email.

There are two ways to fix it:
- In Azure AD, set the Fernbill app's NameID claim to user.mail (their primary email) instead of user.userprincipalname.
- Or turn on Just-in-time provisioning in Fernbill under Settings > Security > Single sign-on, so a user is created the first time someone signs in.

The first is cleaner if your aliases differ from primary emails across the company. Could you let me know which you'd prefer? I'm happy to walk your team through the Azure change on a call.

Sofia
